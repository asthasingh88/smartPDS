SmartPDS Synthetic Demo Dataset
================================

Purpose
-------
This package contains synthetic, internally consistent example data for hackathon prototyping and evaluator demonstrations. It is NOT official government data and should not be represented as actual PDS operational records.

Files
-----
inventory_batches.csv
  Batch-level stock, receipt/expiry dates, supplier, storage zone and inspection status.

dispatch_history_90_days.csv
  90 days of synthetic dispatch records for Rice, Wheat and Sugar. Suitable for prototyping demand aggregation and simple forecasting baselines.

storage_sensor_readings.csv
  Synthetic daily temperature, relative humidity and grain-moisture readings for selected storage zones over 14 days. Use only for demonstrating risk rules; thresholds must be validated by qualified domain experts before real-world use.

audit_anomalies.csv
  Example audit events, stock discrepancy, duplicate challan candidate and FIFO exception.

receipt_challan_examples.csv
  Structured sample receipt/challan fields. These are examples for form validation; they are not scanned document images.

copilot_intent_examples.csv
  Example Hindi/English user questions mapped to query intents. These are starter examples for intent routing, not a trained language model.

evaluator_scenarios.csv
  Eight repeatable scenarios with steps, expected results and safety guardrails.

Important implementation notes
------------------------------
1. FIFO allocation must be deterministic application/backend logic, not generated by an LLM.
2. Calculate stock totals from inventory_batches.csv; do not hardcode totals in Copilot responses.
3. Forecasting estimates should show the history window and assumptions. This dataset is synthetic and small.
4. Age alone does not establish spoilage. Use sensor and inspection information as risk indicators only.
5. Do not treat anomaly flags as proof of fraud.
6. Receipt extraction in this package is structured demo data, not OCR training data.
7. For production, enforce role checks and stock deductions server-side, ideally using Firestore transactions.

Suggested first demo
--------------------
- Ask Copilot for Rice stock.
- Run a 4,000 kg Rice FIFO allocation preview.
- Confirm it and inspect updated batch balances and audit log.
- Open the high-severity audit cases.
- Show the ageing risk warning and explain its evidence.
